# Мои пары — РГАТУ

Android-приложение с удобным расписанием группы **ЗВС-26**, перенесённым из скриншотов пользователя: **48 пар с 5 по 14 октября 2026 года**. Работает офлайн, Android 8.0 и новее.

На старых телефонах нужен актуальный Android System WebView.

## Возможности

- Ближайшая или текущая пара, время, преподаватель, аудитория.
- Выбор дня, обзор всех дней, поиск по предмету, преподавателю и аудитории.
- Видимые окна между занятиями; отдельные звонки в будни и выходные.
- Системные напоминания за 0–180 минут до каждой пары; по умолчанию за 15 минут.
- Восстановление расписания напоминаний после перезагрузки, обновления приложения и изменения времени.
- Редактирование, добавление, удаление, отмена занятий и заметки; отключение напоминания для отдельной пары.
- Светлая/тёмная/системная тема. Импорт и экспорт JSON без разрешения на доступ ко всему хранилищу.

## Установка и уведомления

1. Скачайте `rgatu-schedule.apk` и откройте файл на Android. При необходимости разрешите установку приложений из этого источника.
2. В приложении нажмите на строку напоминаний или шестерёнку.
3. Разрешите **уведомления**, а на Android 12+ — **будильники и напоминания** для точного времени.
4. Нажмите **«Проверить через 10 секунд»** и закройте приложение. Должно прийти тестовое уведомление.

Без разрешения на точное время используется неточный системный будильник; Android может задерживать уведомления. Принудительная остановка приложения в системных настройках прекращает его работу до следующего запуска. Если производитель ограничивает фоновую работу, разрешите её в настройках телефона. Приложение не запрашивает постоянную фоновую службу, доступ в интернет или полное хранилище.

## Данные

Исходный файл: [`app/src/main/assets/schedule.json`](app/src/main/assets/schedule.json). Звонки: `TimeRules.java` и таблицы в `app.js`; автоматическая проверка сверяет их.

Даты **абсолютные**, не повторяющееся недельное расписание. На скриншотах нет расписания на 11 октября или после 14 октября: приложение не придумывает занятия и показывает отсутствие данных. Правый столбец группы ЗКС-26 обрезан, поэтому в этой версии используется полностью видимый столбец ЗВС-26. Время занятий и напоминаний фиксировано в **Europe/Moscow (UTC+3)** и не зависит от часового пояса телефона.

Л — лекция, П — практика, ЛР — лабораторная. Типы занятий сохранены из источника, включая обозначение Л у физической культуры. Изображение со звонками задаёт 85 минут для шестой пары в будни и седьмой в выходные; эти значения сохранены.

При обновлении встроенного файла уже сделанные локальные правки не затираются. Чтобы применить новый файл целиком, используйте импорт или восстановление исходного расписания после экспорта своей копии.

## Скачать новую сборку из GitHub

Откройте **Actions → Android APK → успешный запуск → Artifacts → rgatu-schedule-apk**. Внутри ZIP находится APK. Автосборка запускается при изменениях `main`; её можно запустить кнопкой **Run workflow**.

По умолчанию CI создаёт подписанный APK для разработки и сохраняет его ключ в Actions Cache. После очистки/истечения кеша подпись может измениться; такой APK потребует удаления предыдущей установки. Перед удалением экспортируйте расписание, чтобы сохранить правки.

Для стабильных обновлений настройте закрытые **Repository secrets**:

- `ANDROID_KEYSTORE_BASE64`: ключ подписи в base64;
- `ANDROID_KEYSTORE_PASSWORD`: пароль хранилища и ключа;
- `ANDROID_KEY_ALIAS`: alias ключа (по умолчанию `rgatu`).

Ключи и пароли никогда не добавляются в репозиторий. APK, собранный локально с другим ключом, нельзя обновить сборкой CI с новой подписью.

## Сборка

Проект можно открыть в Android Studio (JDK 17, Android SDK 35). Для сборки без Gradle и сторонних библиотек:

```bash
sdkmanager 'platforms;android-35' 'build-tools;35.0.1'
bash scripts/check.sh
bash scripts/build.sh
```

Для нестандартного расположения SDK задайте `ANDROID_SDK_ROOT`, либо `ANDROID_JAR` и `BUILD_TOOLS_DIR`. Подписанный APK появляется в `dist/rgatu-schedule.apk`.

Для подписи своим ключом задайте `SCHEDULE_KEYSTORE`, `SCHEDULE_KEYSTORE_PASSWORD`, `SCHEDULE_KEY_ALIAS`. Без них создаётся приватный ключ разработки в локальной папке `signing/`; она исключена из Git.

## Проверка

`scripts/check.sh` проверяет 48 записей, отсутствие дубликатов, распределение по датам, аудитории, одинаковые таблицы звонков Java/JS и восстановление будильников. JVM-тест проверяет будние/выходные времена, интервалы, московский часовой пояс и ошибки ввода. `build.sh` дополнительно проверяет подпись и выравнивание APK.

Для проверки интерфейса установите Playwright (`npm install --no-save playwright`, `npx playwright install chromium`) и запустите `node tests/ui.cjs`. Тест проверяет субботнее время, отсутствие данных, поиск, правки, конфликты, безопасный вывод текста, настройки и экран шириной 320 px с уменьшением высоты под клавиатуру.

Уведомления используют `AlarmManager` с неизменяемыми `PendingIntent`, не таймеры внутри веб-страницы. Интерфейс — локальный WebView, файлы и контент извне заблокированы, интернет-разрешения нет. Импорт проверяет размеры, типы и повторы; тексты отображаются с экранированием. Сначала планируются до 200 ближайших напоминаний, затем окно пополняется при их доставке и запуске приложения.
